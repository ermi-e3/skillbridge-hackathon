# 13. Error Handling & Logging

This document details the error handling architecture, exception handling pipelines, RFC 7807 ProblemDetails specifications, and logging strategies across SkillBridge.

---

## 1. RFC 7807 ProblemDetails Standard

SkillBridge uses the IETF standard **RFC 7807 (Problem Details for HTTP APIs)** for all error responses across the backend API.

### Standard Problem Details Structure:
```json
{
  "type": "https://httpstatuses.io/400",
  "title": "Invalid transition",
  "status": 400,
  "detail": "Cannot change status from Shortlisted to Rejected.",
  "code": "applications.invalid_transition",
  "traceId": "0HN1A2B3C4D5E:00000001"
}
```

- `type`: URI identifying the problem type.
- `title`: Short, human-readable summary of the problem type.
- `status`: The HTTP status code generated by the origin server.
- `detail`: A human-readable explanation specific to this occurrence of the problem.
- `code`: Machine-readable error code used by the frontend to trigger specific UI logic or translations.
- `traceId`: Correlation identifier matching server logs for rapid triage.

## 2. Backend Exception Hierarchy & Middleware

The backend separates domain errors from unhandled infrastructure crashes using a clear exception hierarchy:

```
Exception
└── AppException (SkillBridge.Domain.Common)
    ├── BusinessRuleException (Domain rule invariant violated, HTTP 400)
    └── SkillBridge.Application.Common.Exceptions
        ├── RequestValidationException (FluentValidation failure, HTTP 400)
        ├── UnauthorizedException (Authentication failure, HTTP 401)
        ├── ForbiddenException (Authorization / Role / Ownership failure, HTTP 403)
        ├── NotFoundException (Resource does not exist, HTTP 404)
        └── ConflictException (Unique key collision / Concurrency, HTTP 409)
```

### Global Exception Pipeline (`AppExceptionHandler.cs`)
In `backend/src/SkillBridge.Api/Errors/AppExceptionHandler.cs`, the custom `IExceptionHandler` intercepts all unhandled exceptions:

```csharp
public async ValueTask<bool> TryHandleAsync(
    HttpContext httpContext,
    Exception exception,
    CancellationToken cancellationToken)
{
    var (status, code, title, detail) = exception switch
    {
        RequestValidationException ve => (StatusCodes.Status400BadRequest, "validation.failed", "Validation error", ve.Message),
        BusinessRuleException bre => (StatusCodes.Status400BadRequest, bre.Code, bre.Title, bre.Detail),
        UnauthorizedException ue => (StatusCodes.Status401Unauthorized, ue.Code, ue.Title, ue.Detail),
        ForbiddenException fe => (StatusCodes.Status403Forbidden, fe.Code, fe.Title, fe.Detail),
        NotFoundException nfe => (StatusCodes.Status404NotFound, nfe.Code, nfe.Title, nfe.Detail),
        ConflictException ce => (StatusCodes.Status409Conflict, ce.Code, ce.Title, ce.Detail),
        _ => (StatusCodes.Status500InternalServerError, "server.error", "Internal server error", "An unexpected error occurred.")
    };

    logger.LogError(exception, "Handled exception {Code}: {Message}", code, exception.Message);

    await ProblemDetailsWriter.WriteAsync(httpContext, status, code, title, detail, cancellationToken);
    return true;
}
```

## 3. Validation Error Handling

When incoming requests fail FluentValidation checks, the API returns a structured validation problem details response containing an `errors` dictionary:

```json
{
  "type": "https://httpstatuses.io/400",
  "title": "Invalid request",
  "status": 400,
  "detail": "Please correct the invalid fields.",
  "code": "validation.failed",
  "traceId": "0HN1A2B3C4D5E:00000002",
  "errors": {
    "Email": ["A valid email address is required."],
    "Password": ["Password must contain at least one digit and one special character."]
  }
}
```

The frontend utility [frontend/src/app/core/utils/error-formatter.ts](file:///c:/Users/User/SkillBridge/skillbridge-hackathon/frontend/src/app/core/utils/error-formatter.ts) parses this structure and surfaces inline messages directly next to the affected form controls.

## 4. Frontend Error Interception & User Feedback

1. **HTTP Error Formatting:** `extractErrorMessage(error)` in `error-formatter.ts` extracts the most specific error message available:
   - First checks for RFC 7807 `error.error.detail`.
   - If validation errors exist, concatenates the first validation message.
   - Falls back to status-specific defaults (e.g. *"Your session has expired. Please log in again."* for 401).
2. **Real-Time Toast Alerts:** Unhandled operational errors trigger contextual toast notifications via Angular's reactive UI layer.

## 5. Logging Configuration & Strategy

### Configuration in `appsettings.json`:
```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore.Database.Command": "Warning"
    }
  }
}
```

### Logging Principles:
- **Sensitive Data Masking:** Passwords, JWT keys, Brevo API keys, and refresh tokens are strictly excluded from log statements.
- **Trace Correlation:** Every error log entry includes `TraceIdentifier`, enabling instant correlation between client-facing error dialogs and backend server logs.
- **Database Query Logging:** In development mode, EF Core query execution logging is capped at `Warning` to avoid log flooding while highlighting slow queries or unindexed scans.
